# Identity Service production cutover

The manifests in `clusters/production/apps` describe the **final** state. ArgoCD auto-syncs the `production` branch. Do not push that final manifest before the images, Vault secret and application code are ready.

1. Merge the Identity Service refactor branch from `Gauas/account-service` `develop` after review. Its GitHub Action builds PRs without publishing and pushes `gauaslab/identity-service` only on `develop` updates or a manual run selected on `develop`. Publish a HunterJob API image containing local JWT verification. Build/test both images before changing Ingress. The renamed source directory still uses the `Gauas/account-service` remote until that GitHub repository is renamed.
2. Populate Vault `secret/identity-service/production` from the current identity payload. Preserve the existing PostgreSQL `DATABASE_URL`, `JWT_KEYS_JSON` (including active and verify-only keys), issuer, audience, refresh settings, OAuth credentials and queue/Redis configuration. Verify the new image can read it. No database copy is required: the service boundary is renamed, not split.
3. Start the new Identity Service against that database behind its internal Kubernetes Service, without moving public routes yet. Check `/v1/identity/health/ready`, JWKS, login, refresh, logout, profile and the configured OAuth callback. Compare published `kid` values with the tokens already issued by the old service.
4. Roll out the HunterJob API image while the old ForwardAuth route still exists. The old gateway passes the original `Authorization` header; the new HunterJob middleware verifies it independently. Check a valid token, an invalid token and a forged `X-Gauas-*` header. Set `JWKS_URL` to the internal Identity Service endpoint.
5. Apply the final ArgoCD manifest: route `api.gauas.com` to Identity Service and HunterJob by path, remove ForwardAuth middleware and Authorization Service, and keep HunterJob protected routes routed to HunterJob. Confirm login, profile, dashboard, refresh, logout and JWKS externally. Deploy the updated frontend with the refresh endpoint and one private `API_BASE_URL=https://api.gauas.com`.
6. Observe auth errors, JWKS fetches, refresh failures, Identity Service CPU and application latency. Normal HunterJob traffic must not reach Identity Service or perform auth Redis lookups. Run the k6 script in `project/jobhunter/backend/loadtest` against a test environment before high-volume traffic.

The current `identity-service.yaml` references `gauaslab/identity-service:latest` and `secret/identity-service/production`. These are release prerequisites, not resources this Git commit can create. The old `authorization-service` repository is retired but remains recoverable through Git history if rollback is needed.
